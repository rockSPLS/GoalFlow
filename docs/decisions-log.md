# Журнал решений

Коротко: что решили и почему именно так, а не иначе. Основа для раздела README «Технологии и почему».

## Стек и инфраструктура

- **Next.js (App Router) + TypeScript** — интерфейс и небольшая серверная часть в одном проекте: один запуск и один деплой. Сервер понадобится только AI-помощнику — ключ API нельзя держать в браузере. Стек уже знаком, поэтому время уходит на сам продукт, а не на изучение инструментов.
- **Tailwind CSS** — стили прямо в разметке, без отдельных CSS-файлов на каждый компонент; быстрее всего для небольшого проекта.
- **zod** — проверка структуры данных там, где они приходят извне: чтение из localStorage, импорт резервной копии, ответы сервера.
- **lucide-react** — набор иконок.
- **@dnd-kit/core** — перетаскивание задач в календаре и на доске: работает мышью и касанием, объявляет перенос экранному диктору. Отклонено: встроенное перетаскивание браузера (HTML Drag and Drop) — не работает касанием на телефоне и его сложнее оформить.
- **Порт 3002** — порты 3000 и 3001 на машине разработчика заняты другими проектами.
- **`.gitattributes` с `text=auto`** — в репозитории LF, на машине разработчика окончания строк по его ОС (CRLF на Windows, LF на macOS).

## Хранение данных

- **localStorage** — все данные приложения хранятся в браузере пользователя одним JSON-документом. Данные остаются у пользователя, сервер с базой не нужен; лимит около 5 МБ на сайт с запасом покрывает личный список задач и записи времени; из вариантов это самый простой. Отклонены:
  - IndexedDB (с библиотекой Dexie) — больше объём и есть индексы, но асинхронный API и лишняя библиотека не дают выигрыша на таком объёме;
  - серверная БД (MySQL + Kysely) — нужна установка, а при публикации — облачная база, то есть данные ушли бы с устройства пользователя;
  - SQLite в браузере (WASM) — слишком тяжёлое решение для этой задачи.
- **Следствие: данные живут в одном браузере.** Синхронизации между устройствами нет; перенос — через экспорт и импорт.
- **Повреждённые данные не затираются молча** — если сохранённый документ не проходит проверку схемой, его копия сохраняется под отдельным ключом, а приложение начинает с чистого листа. В сообщении об этом есть кнопка «Скачать повреждённые данные»: восстановить их приложение не может, но файл можно поправить вручную или показать специалисту. Так бывает редко: данные правили вручную через инструменты разработчика, их испортило расширение браузера, их записала несовместимая версия приложения или запись оборвалась. Если на копию не хватило места даже после удаления старых копий, изменения не сохраняются вовсе, чтобы не уничтожить старые данные. Отклонено: просто начать заново — пользователь потерял бы данные без предупреждения.
- **«Хранилище копий»** — пункт в блоке «Резервная копия» левого меню (рядом — число копий) открывает экран со списком копий и пояснением: «Данные до восстановления» («Скачать», «Вернуть», «Удалить») и «Повреждённые данные» («Скачать», «Удалить»), с датой сохранения; если копий нет — «Копий нет». Копии временные: хранится по одной каждого вида, новая заменяет старую, чтобы не занимать место в хранилище браузера (около 5 МБ на сайт); об этом, о том, что при очистке данных сайта копии пропадают, и о том, откуда берётся каждый вид копий, написано на экране. Если копию удалили, сообщение, которое на неё ссылалось, тоже убирается. Отклонено: копии без интерфейса — ими можно было воспользоваться, только пока висит сообщение.
- **Ссылки на несуществующие цели и проекты чинятся при загрузке** — задача без живого родителя попадает в «Неразобранные», а не пропадает из всех списков.

## Модель данных

- **Гибкая иерархия «цель → проект → задача»** — связи необязательные: задача без проекта и без цели попадает в «Неразобранные», проект может существовать без цели. Задачу можно записать сразу, а разложить позже; задачи без цели находятся фильтром. Отклонено: строгие три уровня — каждая новая задача требовала бы выбора проекта, а это мешает быстрому вводу.
- **Задача может быть привязана прямо к цели** — родитель задачи: проект, цель или никто («Неразобранные»). Пользователь сам выбирает глубину: «цель → задача» для небольшой цели или «цель → проект → задача» для крупной. Отклонено: задача только в проекте — для маленькой цели пришлось бы заводить проект-пустышку.
- **Один родитель** — у задачи не больше одного проекта, у проекта не больше одной цели. Прогресс цели и потраченное время считаются однозначно. Если задача служит двум целям, это обычно на самом деле две задачи (каждая со своим весом и временем) — её стоит разбить. Отклонено: задача в нескольких проектах или целях с делением веса и времени между ними — цифры прогресса и времени становятся неочевидными, а интерфейс сложнее.
- **Связанные задачи** — задачу можно связать с другими задачами (в том числе из других целей); связь двусторонняя, видна в карточках обеих задач, по ней можно перейти к связанной задаче. На прогресс и время связь не влияет: всё считается только у родителя. (Сначала это было записано как «связанные цели» — связь задачи с чужой целью; уточнено: связываются именно задачи. Поле `relatedGoalIds` в модели заменяется на связи задач в итерации 3.)
- **Удаление не уносит вложенное** — при удалении цели её проекты и задачи остаются, но без цели; при удалении проекта его задачи переходят к цели проекта (или в «Неразобранные», если цели нет). Перед удалением приложение спрашивает подтверждение и говорит, что станет с вложенным. Отклонено: каскадное удаление — одно неосторожное действие стирало бы десятки задач без возможности вернуть.

## Задачи

- **Пять статусов: «К выполнению», «В работе», «На паузе», «На проверке», «Готово»** — кроме обычного пути «начал → закончил» есть этап, когда результат сделан, но ждёт проверки (своей или чужой), и состояние «начата, но отложена» — для крупных задач, которые делаются частями; оно отличается от «К выполнению» тем, что работа уже идёт. «В работе» позволяет отбирать задачи в процессе и раскладывать их по колонкам доски. Отклонены: два статуса «Открыта / Готово» — пропадает разница между начатыми и не начатыми задачами; статусы, которые настраивает пользователь, — лишняя сложность. (Сначала статусов было четыре; «На паузе» добавлен при проектировании учёта времени.)

## Учёт времени

- **Таймер и ручной ввод** — таймер для работы «здесь и сейчас», ручной ввод для того, что забыли засечь. Отклонены: только таймер — забытое время не добавить; только ручной ввод — нужно помнить и вписывать самому.
- **Одновременно идёт один таймер** — запуск на другой задаче останавливает предыдущий: работать над двумя задачами сразу нельзя, а два таймера удваивали бы время.
- **Таймер хранит момент старта, а не счётчик** — прошедшее время считается как «сейчас минус старт», поэтому таймер переживает перезагрузку и закрытие вкладки.
- **Каждый отрезок работы — отдельная запись** (задача, начало, длительность в минутах); из записей складываются суммы по задаче, проекту, цели, за день, неделю и месяц. Записи можно поправить и удалить. Время округляется до минут: отрезок короче 30 секунд не записывается. Одна запись — не длиннее суток: отрезок длиннее делится на части по 24 ч.
- **Таймер и статус связаны:**
  - запуск таймера переводит задачу из «К выполнению» и «На паузе» в «В работе»; «На проверке» статус не меняет — время проверки тоже учитывается, но это отдельный этап;
  - у выполненной задачи таймер не запускается: приложение подсказывает сменить статус, чтобы снова работать над ней — так время случайно не запишется на закрытую задачу;
  - любая смена статуса задачи с идущим таймером (кроме «В работе») останавливает таймер, записывает время и сообщает об этом — иначе можно отметить задачу выполненной и забыть про идущий таймер;
  - после ручной остановки приложение предлагает сменить статус; выбор делает пользователь, по умолчанию статус не меняется.
  Отклонено: запуск из любого статуса переводит в «В работе» — тогда проверка терялась бы как отдельный этап.
- **История статусов записывается** — у каждой задачи список «статус + время смены» (не больше 1000 последних записей). Показ в интерфейсе — позже; записывать начали сразу, потому что прошлую историю задним числом не восстановить. У задач, созданных до появления истории, она начинается с первой смены статуса.
- **Забытый таймер — напоминание через 1 час** с вариантами «Работа продолжается» (следующее напоминание ещё через час), «Остановить сейчас», «Указать время окончания». Без подтверждения пользователя время не меняется. Отклонены: автоостановка — время после порога пропадало бы молча, даже если работа шла; без напоминаний — ошибку легко не заметить. В фоновой вкладке браузер проверяет таймеры примерно раз в минуту, поэтому напоминание может прийти с опозданием до минуты.
- **Время видно везде** — у задачи, суммы у проекта и цели, плюс экран «Время»: итоги за сегодня и за выбранный период по целям. Отклонено: без отдельного экрана — разрез «за день / за неделю» негде увидеть.
- **Период на экране «Затраты времени» — переключатель «Неделя / Месяц / Свой период»** — у недели и месяца стрелки к прошлым периодам, у своего периода — даты «с … по …» (по умолчанию с начала месяца по сегодня). Разбивка по дням (неделя, свой период до 31 дня) или по неделям (месяц, свой период длиннее). Отклонено: готовые кнопки «эта / прошлая неделя, этот / прошлый месяц» — дальше прошлого месяца не заглянуть. (Сначала свой период был отклонён как лишние поля ввода; добавлен в итерации 3 вместе с выгрузкой CSV за выбранный период — отчёт часто нужен за произвольные даты.)
- **Таймер виден в заголовке вкладки** — пока он идёт: «▶ 0:42 · Название задачи — GoalFlow»; при напоминании — «🔔 Таймер идёт 1 ч — GoalFlow». Так работающий таймер и напоминание заметны, даже когда открыта другая вкладка.

## Резервная копия

- **Экспорт в JSON — полная резервная копия**, из неё же данные восстанавливаются. **Экспорт в CSV — записи времени** (дата, цель, проект, задача, длительность) для подсчётов в Excel; восстановить из CSV нельзя, это таблица для анализа. Отклонены: только JSON — время неудобно анализировать в таблицах; ещё и CSV задач — лишний файл, который почти ничего не добавляет к JSON.
- **Восстановление заменяет все данные** — с подтверждением; перед заменой текущие данные автоматически копируются в хранилище браузера (одна копия, каждое восстановление перезаписывает предыдущую — чтобы копии не забили хранилище), так что ошибочный импорт можно откатить: в сообщении после восстановления есть кнопки «Скачать прежние данные» и «Отменить восстановление», а в «Хранилище копий» — «Скачать», «Вернуть», «Удалить», пока копия существует. Файл проверяется схемой (включая формат дат) и ограничен 5 МБ. Идущий таймер не переносится: таймер из файла начался в прошлом и показал бы дни работы, а текущий останавливается без записи — об этом предупреждает окно подтверждения. При отмене восстановления таймер возвращается вместе с прежними данными: его старт в прошлом, поэтому сразу появится напоминание, где можно указать время окончания, — время не теряется и не приписывается лишнее. Отклонено: слияние с текущими данными — пришлось бы решать конфликты одинаковых записей и не задвоить время; сложно и долго.

- **Порядок в списках — по времени создания; выполненные скрыты** — смена статуса (запуск таймера, пауза, проверка) задачу не двигает: строка не «уезжает» из-под руки. Выполненные по умолчанию скрыты, внизу списка — «Показать выполненные (N)» (сначала недавно выполненные); счётчики в боковой панели тоже считают только невыполненные. Отклонены: сортировка по статусу — задача прыгает вверх при запуске таймера; выполненные на своих местах — смешиваются с открытыми; пересортировка при следующем открытии экрана — порядок то один, то другой.

- **Обязательно только название** — у задачи всегда есть статус (по умолчанию «К выполнению») и место (по умолчанию «Неразобранные»), вес без указания считается за 1; остальные поля необязательные. Обязательный дедлайн или приоритет превратил бы быструю запись задачи в заполнение формы.
- **Дедлайн — только дата** (без времени); задача с прошедшей датой подсвечивается как просроченная. Отклонено: дата и время — для личных задач обычно лишнее, поле ввода сложнее.
- **Просроченная задача — значок «часы с восклицательным знаком» перед названием**, вдобавок к красной дате дедлайна (подсказка «Просрочено»). Значок прямо говорит «время вышло» и не путается с красным флажком высокого приоритета. Отклонены: название красным — красный текст хуже читается, а в подборке «Просроченные» красным стал бы весь список; восклицательный знак в круге — общий сигнал «внимание» без привязки ко времени; огонёк — читается как «срочно», рядом с флажком приоритета два похожих знака; календарь с крестиком — крестик похож на «отменено».
- **Приоритет — «Высокий / Средний / Низкий» или без приоритета.** Отклонены: один флажок «Важно» — без оттенков; P1–P4 — непривычно.
- **Теги — свободные, с подсказкой уже существующих** (чтобы не плодить «работа» и «Работа»), цвет назначается автоматически. Подсказки — выпадающий список под полем; подсказка добавляется только после явного выбора (стрелками или кликом), иначе Enter добавляет набранный текст.
- **У задачи — не больше 5 тегов**, иначе теги перестают выделять задачи и фильтр по тегу теряет смысл. Когда тегов 5, вместо поля ввода карточка подсказывает снять один. Задачи из старых данных или файла копии, где тегов больше, загружаются как есть — добавить новый тег к ним можно, только сняв лишние.
- **Справочник тегов пополняется сам** — тег запоминается, как только его впервые поставили задаче, и остаётся в подсказках, даже когда его сняли со всех задач. Удалить тег из справочника — крестиком в списке подсказок; если тег стоит у задач, приложение спрашивает подтверждение и убирает его и у них. (Сначала тег существовал, только пока стоит хоть у одной задачи, — снятый тег пропадал из подсказок; уточнено владельцем.) Отклонены: справочник, который заполняют заранее, — лишний шаг перед первым тегом; отдельный экран «Теги» с переименованием — больше работы, пока не нужен.
- **Карточка задачи — панель иконок** (оценка SP, дедлайн, приоритет, теги, связанные задачи, затраты времени) с всплывающими подсказками: заполненные поля видны плашками, по клику на иконку или плашку раскрывается одно поле. Это постепенное раскрытие — пустые поля не занимают места. Отклонены: все поля сразу — карточка длинная даже у пустой задачи; кнопка «Добавить поле» с меню — два клика вместо одного.
- **Описание — поле сразу под названием задачи**, а не за иконкой панели: это основное содержание задачи, его должно быть видно без лишнего клика. (Сначала описание было в панели иконок; уточнено при выборе иконок.)
- **Подпись места задачи — «Цель / проект»**, варианты в списке — «Цель: проект», «Цель (без проекта)», проекты без цели — по названию. Отклонено: «Где лежит» — неудачное название.

## Прогресс

- **Прогресс цели и проекта — по весу задач:** сумма весов выполненных задач делить на сумму весов всех задач (у цели — включая задачи её проектов). Прогресс вычисляется на лету из задач и нигде не хранится, поэтому не может разойтись с реальным состоянием. Отклонены: простой счёт задач — большая и мелкая задача весили бы одинаково; среднее по проектам — проект из одной задачи весил бы как проект из двадцати; частичный прогресс задачи по затраченному времени — потраченное время не равно сделанной работе (задача может съесть всю оценку и быть готовой наполовину или превысить её и показать больше 100 %), а ещё понадобилась бы вторая оценка в часах.
- **Шкала веса — числа Фибоначчи 1, 2, 3, 5, 8** (как story points в Agile): чем крупнее задача, тем грубее оценка, и шкала это отражает. Вес необязателен: если не указан, задача весит 1, и без весов прогресс совпадает с долей выполненных задач. Отклонено: три уровня (до полудня / до 2 дней / больше) — проще, но грубее.
- **Вес подписывается «SP» (story points)** — например, «3 SP», чтобы его не путали с часами. Расшифровка значений выводится там, где вес выставляется, и во всплывающей подсказке при наведении на вес: 1 — мелочь (до часа), 2 — пара часов, 3 — около дня, 5 — 2–3 дня, 8 — неделя и больше (стоит разбить).
- **В прогресс идёт только «Готово»;** задача «На проверке» считается невыполненной — иначе цель показала бы 100 %, пока результат ещё не принят. По той же причине процент округляется вниз: 100 % — только когда готово всё.
- **Время показывается отдельно от прогресса** — рядом с задачей и целью, а не внутри процента.

## Интерфейс

- **Фильтры — панель условий на экране «Все» + готовые и сохранённые подборки** — условия: статус, приоритет, теги, дедлайн (просрочено / сегодня / эта неделя), «без цели», «больше 4 ч». Готовые подборки: «Без цели», «Застряли (больше 4 ч)», «Дедлайн на этой неделе», «Просроченные». Любое сочетание условий сохраняется под своим именем как подборка. Отклонены: текстовый синтаксис запросов — новичку нужно учить синтаксис (может появиться позже вместе с быстрым вводом); только готовые подборки — нет гибкости.
- **В условиях фильтра — мультивыбор** — в статусе, приоритете, тегах и дедлайне можно отметить несколько значений: внутри условия — «любое из выбранных», между условиями — «и» (например, «теги: работа или учёба» и «приоритет: высокий или средний»). Поле — мультиселект с чипами: выбранные значения плашками прямо в поле (с крестиком), строку списка выбирают кликом целиком, выбранные отмечены галочкой. Поиск печатается прямо в поле — только в тегах, где список длинный; в статусах, приоритетах и дедлайнах по 3–5 пунктов, поиск там мешал бы. Сохранённые раньше наборы с одним значением переводятся в новый формат при загрузке. (Сначала в каждом условии выбиралось одно значение из обычного выпадающего списка; уточнено владельцем: при множестве тегов такой список неудобен.) Отклонены: мультивыбор с поиском во всех условиях — поиск по 3–5 пунктам лишний; поиск только у тегов без мультивыбора — не отобрать «В работе» вместе с «На паузе».
- **Подборки — ряд над фильтрами на экране «Все», а не раздел левого меню** — у каждой подборки число невыполненных задач, клик применяет её условия, у своих подборок — крестик удаления с подтверждением. Ряд не выше двух строк, чтобы не сдвигать список задач; если подборки не помещаются — «Показать все подборки». Левое меню отвечает на вопрос «где лежит задача» (цели, проекты), а подборки — это сохранённые фильтры, им место рядом с фильтрами; в меню их множество отодвигало бы цели. Из любого экрана подборка открывается через палитру команд (Ctrl+K). (Сначала сохранённые наборы назывались «виды» и стояли разделом левого меню; переименованы и перенесены по решению владельца.) Отклонены: раздел левого меню (в том числе сворачиваемый внизу) — смешивается с целями и проектами, фильтры и подборки оказываются в разных местах; выпадающий список подборок — их не видно, пока не откроешь.
- **«Затраты времени»** — так называются и экран (бывший «Время»), и блок в карточке задачи; в ручном вводе поле «Дата», а не «День».
- **Выгрузка CSV — на экране «Затраты времени», а не в «Резервной копии»** — выгружается период, который сейчас на экране (неделя или месяц, стрелками — прошлые), всё время целиком или свой период «с … по …». Таблица времени — это отчёт, ей место рядом с итогами; резервная копия — про сохранение и восстановление данных. Отклонено: кнопка в блоке «Резервная копия» — выгружает всё сразу, период не выбрать.
- **В карточке задачи вес называется «Оценка SP»** — это оценка размера задачи в story points, и так понятнее, что её ставят заранее.
- **Виды задач: сейчас — календарь с перетаскиванием, доска — позже** — в календаре задачи с дедлайном разложены по дням месяца, перетаскивание на другой день меняет дедлайн. Календарь появляется вместе с дедлайнами, поэтому делается в этой итерации. Доска по статусам — после горячих клавиш и быстрого ввода, если останется время: виды читают одни и те же данные, поэтому доску можно добавить позже без переделок. Перетаскивание — библиотека `@dnd-kit`. Отклонены: календарь и доска сразу — около дня работы, под угрозой горячие клавиши; оба вида позже — дедлайн без календаря виден только в списке.
- **Календарь — переключатель «Список / Календарь» на экране «Все»**, фильтры действуют и на календарь; доска позже встанет третьим вариантом. Выполненные задачи видны в календаре зачёркнутыми — видно, что было сделано. Отклонены: отдельный пункт «Календарь» в меню — без фильтров; переключатель на каждом экране — больше работы при той же пользе; скрывать выполненные — не видно, что сделано в срок.
- **Календарь — компактный месяц + список задач выбранного дня** — в клетке месяца число задач, по клику на день под месяцем открывается список его задач с параметрами (статус, приоритет, SP, теги, цель или проект), как в обычном списке. Задачу тянут за ручку ⠿ на день месяца; ниже — список «Без дедлайна», откуда задачу тоже можно перетащить на день. Так видно и месяц, и что за задачи, и понятно, за что тянуть. Отклонены: названия задач плашками прямо в клетках (первый вариант) — в узкой клетке видно только начало названия и непонятно, что можно тянуть; список по датам без сетки месяца — дни без задач не видны, перетаскивать некуда.
- **Доска — третий вид на экране «Все»: «Список / Календарь / Доска»**, Shift+V переключает три вида по кругу. Колонка на каждый из пяти статусов; задачу тянут в другую колонку за всю карточку — за название, ручку ⠿ или пустое место (клик без сдвига мыши, как и раньше, открывает карточку), и статус меняется так же, как в карточке: идущий таймер останавливается с уведомлением, смена попадает в историю статусов. Фильтры и подборки действуют и на доску; если отобраны не все статусы, остальные колонки остаются пустыми — в них можно перенести задачу. Отклонены: отдельный пункт меню — там не было бы фильтров; доска на каждом экране цели и проекта — больше работы, начали с одной доски; перенос только за ручку ⠿, как в календаре, — на доске интуитивно тянуть за название (уточнено владельцем после проверки).
- **Колонка «Готово» — выполненные за последние 7 дней**, внизу «Показать все (N)»: недавно сделанное видно, а колонка не растёт месяцами. Если фильтр отбирает «Готово», видны все выполненные. Отклонены: все выполненные сразу — колонка быстро становится длинной; свёрнутая колонка, как выполненные в списке, — не видно, что сделано недавно.
- **Порядок карточек в колонке — по приоритету, затем по дедлайну** (ранний выше, без дедлайна — в конце), затем по времени создания; в «Готово» — сначала недавно выполненные. Важное и срочное наверху. Отклонены: по времени создания, как в списке, — важная задача теряется в середине колонки; свой порядок перетаскиванием внутри колонки — нужны новое поле в данных и ещё одна библиотека.
- **Доска шире остальных экранов** — в режиме доски основная область занимает всю ширину; если пять колонок не помещаются (телефон, узкое окно браузера — уже примерно 1250 px вместе с боковой панелью), колонки листаются вбок внутри доски, а страница вбок не сдвигается. Пять колонок в полосе 768 px — около 145 px на колонку, названия задач обрезаются. Отклонено: прежняя ширина с прокруткой вбок и на компьютере.
- **Карточка задачи в окне — на доске и из сообщения «Задача «…» добавлена в «…»»** — та же карточка, что в списке, только поверх текущего экрана; экран не меняется, окно закрывается по Esc, крестику или клику по фону. Связанная задача из карточки в окне открывается в этом же окне. В списках карточка, как и раньше, раскрывается под строкой, а палитра команд переходит к задаче. Отклонены: карточка под доской — её приходится искать прокруткой; карточка прямо в колонке — слишком узко; окно и в палитре — палитра тогда перестала бы переносить к задаче.

- **Раскладка «боковая панель + список»** — слева блок «Задачи» («Неразобранные», «Все») и цели с проектами (отступ в одну ступень, прогресс рядом с названием), справа задачи выбранной цели или проекта, сгруппированные по проектам. Видно одновременно, где находишься и как продвигается цель. (Сохранённые подборки потом встали не в панель, а над фильтрами на экране «Все».) Отклонены: карточки целей — до задач добираться дольше, каждый шаг на отдельном экране; один общий список с путём у каждой задачи как основной вид — иерархия видна только в подписях, прогресс цели показать негде (как дополнительный вид такой список есть — «Все»).
- **Блок «Задачи»: «Неразобранные» и «Все»** — «Неразобранные» — задачи без цели и проекта: записала сразу, разложу потом. «Все» — все задачи одним списком, у каждой подписано, где она лежит. Отклонено название «Входящие» (калька Inbox из методики GTD) — по-русски звучит как почта.
- **Светлая тема по умолчанию + кнопка переключения на тёмную** — выбор запоминается в браузере. Сохранённую тему до первой отрисовки выставляет маленький скрипт в `<head>`, поэтому страница не мигает светлой (приём из руководства Next.js «Preventing flash before hydration»). Системная тема не учитывается: при первом заходе тема светлая, даже если в системе выбрана тёмная. Отклонено: тема по настройке системы без кнопки — пользователь не может выбрать тему для этого приложения отдельно.

## Быстрые действия

- **Горячие клавиши — сочетания с Shift (и Ctrl+K), а не одиночные клавиши** — Shift+N — быстрый ввод задачи, Shift+V — «Список / Календарь / Доска», Shift+X — отметить выполненной (и обратно), Shift+S — таймер, Ctrl+K или Shift+K — палитра команд, «?» — шпаргалка по клавишам. Одиночную клавишу легко нажать случайно, и что-то произойдёт молча; Shift+буква случайно не нажмёшь, а браузер такие сочетания сам не использует. Клавиши работают в любой раскладке (буквы — по физической клавише), не срабатывают, пока курсор в поле ввода (кроме Ctrl+K). Shift+X и Shift+S действуют на текущую задачу — строку с фокусом, иначе задачу, с которой только что работали этими клавишами, иначе задачу с открытой карточкой (после Shift+X строка уходит в выполненные, и повторное нажатие возвращает задачу обратно; открытая карточка при этом остаётся открытой); по строкам ходят Tab и стрелками ↑↓ (стрелки — только когда фокус уже в списке), фокус обведён рамкой. После Shift+X — сообщение с кнопкой «Отменить». Отклонены: одиночные клавиши (N, X, J/K) — случайное нажатие срабатывает молча; всё с Alt — часть сочетаний занята браузером и Windows; только палитра и «?» — каждое действие через лишний шаг.
- **Ctrl+K и Shift+K — оба открывают палитру** — Ctrl+K привычен по другим приложениям (в браузере он ставит курсор в поиск адресной строки, но сайт может его перехватить), Shift+K — по общей схеме «Shift+буква».
- **Шпаргалка по клавишам — клавиша «?», кнопка с иконкой клавиатуры рядом с переключателем темы и пункт в палитре**, чтобы её мог найти тот, кто не знает про «?».
- **Быстрый ввод — метки со значками** — `#тег`, `!1 !2 !3` (высокий / средний / низкий приоритет), `@цель или проект`, `^дедлайн` (сегодня, завтра, послезавтра, пн…вс, 25.10, 25.10.2026), `3sp` (оценка). До создания под полем видно, что распознано. Обычные слова никогда не принимаются за метки, поэтому результат предсказуем. Отклонены: обычные слова («завтра», «высокий») — слово уходит из названия, даже если имелось в виду другое; без разбора — поля пришлось бы заполнять в карточке.
- **Метки с автокомплитом; несуществующая цель или проект не создаётся** — после `@`, `#` и `^` выпадает список (цели и проекты, теги, варианты дат); выбранное становится плашкой под полем. Если после `@` указано то, чего нет, или дата не распознана, приложение подсказывает, и задача не создаётся, пока это не исправить; новый тег создаётся, как в карточке. Отклонены: создавать цель или проект прямо из быстрого ввода — опечатка тихо плодит пространства; ошибка только после Enter — поздно.
- **Быстрый ввод — окно по Shift+N с любого экрана и поля «Новая задача» на экранах** — без `@` задача попадает в открытую цель или проект, иначе — в «Неразобранные». Если задача ушла в другое пространство или добавлена из окна Shift+N (окно закрывается, и без сообщения не видно, что задача создана), появляется сообщение «Задача «…» добавлена в «…»»: по названию задачи — её карточка в окне поверх экрана, по названию пространства — переход туда, крестик закрывает сообщение (экран не меняется). (Сначала название задачи переводило на её экран с открытой карточкой; изменено, когда появилась карточка в окне. Сначала же сообщение после окна Shift+N появлялось, только если задача ушла в другое пространство.) Отклонены: только окно или только поля на экранах — одно из двух мест работало бы иначе.
- **Сообщение внизу экрана исчезает само на втором действии в другом месте страницы** (клик или переход по Tab), а также по крестику и Esc. Не на первом: первым кликом часто переходят к задаче, а сообщение ещё нужно — например, чтобы нажать «Отменить». (Сначала сообщение висело до крестика или Esc и мешало, когда уже перешли к другим задачам.) Отклонены: исчезновение по таймеру — сообщение может пропасть, пока его читают; исчезновение на первом действии — кнопку в сообщении не успеть нажать.
- **Палитра команд (Ctrl+K / Shift+K)** — одно поле поиска поверх экрана: задачи по названию (открыть карточку), пространства — цели, проекты, подборки, «Неразобранные», «Все», «Затраты времени» (перейти), действия — новая задача, новая цель, тема, скачать копию, горячие клавиши (выполнить). Палитра заодно служит поиском по задачам. Отклонено: без действий — тогда часть действий с клавиатуры недоступна, раз отдельных клавиш мало.

## Осознанно не закрыто

- **Очистка данных сайта в браузере удаляет записи.** Защита — экспорт резервной копии.
- **Когда GoalFlow закрыт, напоминаний о таймере нет** — веб-страница без открытой вкладки ничего не выполняет. Таймер при этом не теряется: при следующем открытии напоминание появляется сразу. Закрыть можно только push-уведомлениями (сервер + Service Worker), что противоречит хранению данных у пользователя.
- **При нескольких открытых вкладках напоминание появляется в каждой** — закрывается ответом в любой из них. Договорённость вкладок «кто напоминает» отложена.
- **Итоги на экране «Время» не включают идущий таймер** — время попадает в итоги после остановки; идущее время видно в строке задачи и в заголовке вкладки.
- **`npm audit`: 5 уязвимостей high** в цепочке `eslint-config-next` → `@next/eslint-plugin-next` → `fast-glob` → `micromatch` → `braces` (отказ в обслуживании при специально составленных шаблонах путей). Затрагивает только линтер на машине разработчика, в сборку приложения не попадает (`npm ls --omit=dev braces` пуст). Предлагаемое `npm audit fix --force` откатило бы `eslint-config-next` до версии 14, несовместимой с Next.js 16. Закрыть: обновить `eslint-config-next`, когда выйдет версия с исправленной зависимостью.
