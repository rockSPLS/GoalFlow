# Журнал решений

Коротко: что решили и почему именно так, а не иначе. Основа для раздела README «Технологии и почему».

## Стек и инфраструктура

- **Next.js (App Router) + TypeScript** — интерфейс и небольшая серверная часть в одном проекте: один запуск и один деплой. Сервер понадобится только AI-помощнику — ключ API нельзя держать в браузере. Стек уже знаком, поэтому время уходит на сам продукт, а не на изучение инструментов.
- **Tailwind CSS** — стили прямо в разметке, без отдельных CSS-файлов на каждый компонент; быстрее всего для небольшого проекта.
- **zod** — проверка структуры данных там, где они приходят извне: импорт резервной копии, ответы сервера.
- **lucide-react** — набор иконок.
- **Порт 3002** — порты 3000 и 3001 на машине разработчика заняты другими проектами.
- **`.gitattributes` с `text=auto`** — в репозитории LF, на машине разработчика окончания строк по его ОС (CRLF на Windows, LF на macOS).

## Хранение данных

- **localStorage** — все данные приложения хранятся в браузере пользователя одним JSON-документом. Данные остаются у пользователя, сервер с базой не нужен; лимит около 5 МБ на сайт с запасом покрывает личный список задач и записи времени; из вариантов это самый простой. Отклонены:
  - IndexedDB (с библиотекой Dexie) — больше объём и есть индексы, но асинхронный API и лишняя библиотека не дают выигрыша на таком объёме;
  - серверная БД (MySQL + Kysely) — нужна установка, а при публикации — облачная база, то есть данные ушли бы с устройства пользователя;
  - SQLite в браузере (WASM) — слишком тяжёлое решение для этой задачи.
- **Следствие: данные живут в одном браузере.** Синхронизации между устройствами нет; перенос — через экспорт и импорт.

## Модель данных

- **Гибкая иерархия «цель → проект → задача»** — связи необязательные: задача без проекта попадает во «Входящие», проект может существовать без цели. Задачу можно записать сразу, а разложить позже; задачи без цели находятся фильтром. Отклонено: строгие три уровня — каждая новая задача требовала бы выбора проекта, а это мешает быстрому вводу.
- **Один родитель** — у задачи не больше одного проекта, у проекта не больше одной цели. Прогресс цели и потраченное время считаются однозначно; темы, которые проходят через несколько проектов, отмечаются тегами. Отклонено: задача в нескольких проектах — пришлось бы решать, как делить время и прогресс между целями, и усложнять интерфейс.

## Осознанно не закрыто

- **Очистка данных сайта в браузере удаляет записи.** Защита — экспорт резервной копии (итерация 2).
- **`npm audit`: 5 уязвимостей high** в цепочке `eslint-config-next` → `@next/eslint-plugin-next` → `fast-glob` → `micromatch` → `braces` (отказ в обслуживании при специально составленных шаблонах путей). Затрагивает только линтер на машине разработчика, в сборку приложения не попадает (`npm ls --omit=dev braces` пуст). Предлагаемое `npm audit fix --force` откатило бы `eslint-config-next` до версии 14, несовместимой с Next.js 16. Закрыть: обновить `eslint-config-next`, когда выйдет версия с исправленной зависимостью.
